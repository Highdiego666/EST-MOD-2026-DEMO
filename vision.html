EST·MOD · Dirección del producto

Un nuevo sistema de estacionamientos, empezando por una sucursal.

La meta es sustituir gradualmente el software heredado con una plataforma propia, basada en Linux, que conecte operación física, administración y pagos web.

Primera instalación: 1 sucursalInterfaz web + agentes LinuxExpansión modular posterior

Qué debe resolver la primera versión

Operación

Entradas, tickets y salidas

Registrar estancias, aplicar tarifas y tolerancias, confirmar pagos y controlar el ciclo de acceso con los equipos acordados.

Administración

Visibilidad operativa

Usuarios, permisos, cobros, reportes, auditoría de aperturas e incidencias de máquinas.

Promociones

Descuentos verificables

Generación e impresión de QR, validación de reglas y canje único controlado por el servidor.

Autoservicio

Pago desde el celular

Consulta del ticket y pago mediante un proveedor externo en un portal web seguro, sin instalar aplicaciones.

Cómo se conectarán los componentes

Dentro de la sucursal

Servidor Linux local

FastAPI, PostgreSQL, tarifas, cobros, auditoría y datos operativos. Los dispositivos se conectan mediante servicios Linux y adaptadores validados.

Acceso por internet

Portal y acceso remoto protegido

Servicios HTTPS para consulta y pago móvil; comunicación restringida con el sistema local. La base de datos no se publica en internet.

Continuidad: si se interrumpe internet, la operación local prevista debe seguir con los métodos presenciales disponibles. No se presumen pagos remotos ni aperturas exitosas durante una falla de enlace.

Ruta de implementación

01

Diagnóstico de una sucursal

Mapear SISCAR, reglas tarifarias, equipos y protocolos con el área técnica.

02

Software operativo y datos persistentes

Autenticación, backend, tickets, caja, reportes y pruebas de integridad en PostgreSQL.

03

Integración de máquinas

Conectar barreras, expedidoras y paystations compatibles, con simulación, pruebas de banco y pruebas supervisadas.

04

Pago web y aceptación

Validar pagos, recuperación de fallas y operación paralela antes de considerar sustituido el sistema anterior.

Capacidades reservadas para crecer

Reconocimiento de placas, membresías, pensiones, centros comerciales, facturación automatizada, más proveedores de pagos y nuevas sucursales son posibles extensiones. No forman parte automáticamente de la primera implementación.

Sobre esta demo: todos los datos y equipos que aparecen en el dashboard son ficticios. El sitio no controla barreras, no consulta sistemas de producción, no almacena datos reales y no procesa pagos.
